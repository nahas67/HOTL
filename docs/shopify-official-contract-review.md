# Shopify contract review for the Gate C pilot

Reviewed 2026-09-28 against current official Shopify documentation. The runtime pins Admin GraphQL `2026-07`. This is **documentation research and local code review**, not a real merchant installation or provider transaction.

| Contract | Review result | HOTL consequence |
| --- | --- | --- |
| [2026-07 `productVariantsBulkUpdate`](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/productVariantsBulkUpdate) | Mutation shape and `write_products` scope match the pinned implementation. The installing user also needs permission to update product variants. | Verify the actual app/user permission in the authorized development store and retain user-error evidence. No schema-breaking mutation change was found. |
| [Access scopes](https://shopify.dev/docs/apps/build/authentication-authorization/manage-access-scopes) | Shopify evaluates granted scopes and user permissions; a write scope may cover its corresponding read capability, but does not grant the user's product-update permission. | Request only `read_products`, `write_products`, `read_inventory` and `read_locations`; verify actual granted scopes and user permission in staging. |
| [Partner development-store plan field](https://shopify.dev/docs/api/admin-graphql/latest/objects/shopplan) and [development stores](https://shopify.dev/docs/apps/build/stores/development-stores) | `plan.partnerDevelopment` supports HOTL's intentionally narrow provider check. | A different store class may fail closed. Do not weaken the development-store gate to make a pilot pass. |
| [Shop-scoped subscriptions](https://shopify.dev/docs/api/admin-graphql/latest/queries/webhookSubscriptions) and [subscription creation](https://shopify.dev/docs/api/admin-graphql/latest/mutations/webhookSubscriptionCreate) | The owner-triggered shop-scoped registration/read-back path is consistent with the API. App-configured subscriptions have a different lifecycle. The webhook payload API version is controlled by app configuration, separate from the pinned Admin GraphQL version. | Record the development app's webhook API version and test the actual payloads. Monitor whether expected subscriptions still exist. |
| [Webhook verification and deliveries](https://shopify.dev/docs/apps/build/webhooks/verify-deliveries) | Shopify requires raw-body HMAC validation and delivery deduplication. Its webhook page says new-secret HMAC generation may take up to one hour after secret rotation. | HOTL keeps current/previous keys during a bounded overlap of at most 30 days. After separately verified Shopify revocation, the operator may configure at most one further hour of old-key acceptance, then must remove the old key. This local timestamp is not proof of Shopify revocation. Delivery health is not externally verified. |
| [Client-secret rotation](https://shopify.dev/docs/apps/build/authentication-authorization/manage-credentials) | Shopify says the old secret stays active until explicitly revoked; webhooks use the oldest unrevoked key. Stored access tokens are pinned to the secret that minted them and must be replaced/re-pinned before revocation. | Keep both keys during the finite overlap, use the new key for OAuth, verify token migration, then separately revoke the old secret in Dev Dashboard and record that external evidence. HOTL does not automate bulk token migration or provider revocation. |
| [OAuth access-token lifecycle](https://shopify.dev/docs/apps/build/authentication-authorization/access-tokens) | Real token acquisition, refresh and secret rotation have not run. Token replacement and ambiguous refresh behavior must be exercised against the installed app's grant type. | Serialize the real shop lifecycle operationally and verify rotation/reconnection in staging. Treat ambiguous refresh conservatively. Never expose tokens in evidence. |
| [GraphQL Admin API limits](https://shopify.dev/docs/api/usage/limits) | Limits are based on query cost and throttling. | Bounded local pagination/retry exists; deployed cost telemetry and load behavior remain unverified. |
| [Privacy compliance webhooks](https://shopify.dev/docs/apps/build/compliance/privacy-law-compliance) | Distribution requirements are broader than this single development-store pilot. | Keep app-store distribution as a later gate; do not claim it is implemented. |

No official documentation finding changes the present evidence level: Shopify OAuth, sync, webhook and price paths remain **M2 local verified** in the [maturity register](program-maturity-register.md). The Gate C evidence package must record actual provider request IDs, app versions, store classification, confirmed old-secret revocation time and observed results without tokens or cookies. The contract pages were rechecked on 2026-09-28; research is not provider evidence.
