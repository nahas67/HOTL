# Official Shopify baseline — reviewed 2026-09-28

This is documentation research for the Gate C pilot, not evidence of a live Shopify installation or request. The runtime remains pinned to Admin GraphQL API version 2026-07. As of this review date, Shopify documents 2026-07 as the latest stable version and 2026-10 as a release candidate. No concrete incompatibility was found that justifies changing the pinned version; do not adopt the release candidate for this drill.

## Findings relevant to the implemented path

- **Versioning:** [Shopify API versioning](https://shopify.dev/docs/api/usage/versioning) and the [2026-07 release notes](https://shopify.dev/release-notes/2026-07) are the version baseline. The [2026-10 release notes](https://shopify.dev/release-notes/2026-10) identify the next release candidate. Actual negotiated/request version remains externally unverified because no request was sent.
- **Authentication:** The [authentication overview](https://shopify.dev/docs/apps/build/authentication-authorization) and [standalone app authorization-code grant](https://shopify.dev/docs/apps/build/authentication-authorization/authenticate-standalone-apps?lang=node) support the existing server-side OAuth authorization-code pattern for this standalone app. Actual app registration, redirect allowlist, installation, granted scopes, token exchange, encrypted persistence, and negative tests remain unverified.
- **Token lifecycle:** [Access-token documentation](https://shopify.dev/docs/apps/build/authentication-authorization/access-tokens) describes access and refresh token handling for expiring offline tokens. The implementation requests expiring access; no real token was obtained or inspected. Tokens must remain server-side and encrypted.
- **Scopes and user permissions:** [Access scopes](https://shopify.dev/docs/apps/build/authentication-authorization/manage-access-scopes) do not replace the installing user's resource permissions. The local flow requests product and inventory/location reads plus product writes. Staging must verify actual granted scopes and the user's ability to update product variants.
- **Development stores:** Shopify's [development-store guide](https://shopify.dev/docs/apps/build/stores/development-stores) distinguishes test stores and transaction capabilities. A development-store drill cannot be represented as a real-money checkout or production transaction.
- **Price mutation:** The versioned [productVariantsBulkUpdate contract](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/productVariantsBulkUpdate) requires product-write scope and user permission; the mutation applies to variants of one product and returns user errors that the caller must inspect. HOTL's local operation targets one variant and checks provider errors. This contract review does not prove that Shopify accepted a request.
- **Webhooks:** Shopify's [webhook subscription guidance](https://shopify.dev/docs/apps/build/webhooks/subscribe) describes app-specific and shop-specific lifecycles. The current workflow is owner-triggered and shop-scoped; actual registration, read-back, delivery, payload API version, raw-body HMAC verification, inbox durability, and authoritative reconciliation remain unverified. HTTP acknowledgement alone is not reconciliation.
- **Credential rotation:** Shopify's [credential management guidance](https://shopify.dev/docs/apps/build/authentication-authorization/manage-credentials) and [webhook verification guidance](https://shopify.dev/docs/apps/build/webhooks/verify-deliveries) describe old-secret/revocation and webhook signature transition behavior, including a delay of up to one hour. HOTL has a bounded local overlap and grace policy; external secret rotation, token migration, and Shopify-side revocation remain unverified.
- **Rate limits:** Shopify's [GraphQL Admin API rate-limit documentation](https://shopify.dev/docs/apps/build/apis/graphql-admin/rate-limits) describes cost-based throttling. Actual throttle behavior and deployed telemetry have not been tested.

## Conclusion

No documentation finding requires changing API version or relaxing a safety gate. The current findings support proceeding with the documented, isolated, owner-operated development-store drill only after the missing owner authority and staging prerequisites are satisfied. Documentation research does not promote OAuth, read sync, webhooks, price writes, or revocation beyond local maturity.
